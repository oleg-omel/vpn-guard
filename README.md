# VPN Guard

Menu bar kill-switch для выбранных приложений и сайтов. Пока трафик не идёт через VPN — они отрезаны от интернета.

```bash
./scripts/install.sh      # сборка + установка (нужен sudo)
./scripts/uninstall.sh
```

Списками управляют из значка щита в строке меню или из CLI: `vpnguardd add-app /Applications/Telegram.app`, `add-site example.com`, `list`, `status`, `check`.

## Как работает
- **Детекция** (`vpnguardd`, root): слушает PF_ROUTE-сокет ядра — просыпается только при изменении маршрутов/интерфейсов, без опроса. Спрашивает у таблицы маршрутов (`route get 1.1.1.1`, а также IPv6), через какой интерфейс уйдёт трафик. `utun*/ipsec*/ppp*/tun*/tap*/wg*` = VPN. Работает и с VPN, которые ставят маршруты `0/1 + 128/1` вместо default. Раз в 2 минуты — страховочная проверка.
- **Приложения**: все процессы внутри `.app` (включая хелперы) замораживаются `SIGSTOP`, при возвращении VPN — `SIGCONT`. Пока VPN нет, раз в 2 с ловятся вновь запущенные процессы. Приложение в это время «не отвечает» — это и есть блокировка.
- **Сайты**: блок в `/etc/hosts` (домен и `www.`) + правила `pf` (якорь `com.apple/vpnguard`) на их IP.
- Конфиг: `/Library/Application Support/VPNGuard/config.json`, лог: `/var/log/vpnguard.log`.

- **Доверенные Wi-Fi**: если вы подключены к сети из списка (и трафик реально выходит через неё), защита приостанавливается; в любой другой сети включается снова. Имя сети читает демон от root (обычному процессу macOS его скрывает). CLI: `vpnguardd add-wifi <ssid>`.

## Ограничения
- Не добавляйте в список сам VPN-клиент — он заморозится и не сможет переподключиться.
- Поддомены надо добавлять явно (hosts не знает wildcard); IP-блок покрывает только то, что отдал DNS. Браузерный DoH и уже открытые соединения могут обходить hosts, pf их режет по IP.
- Приложения Apple, чей сетевой код живёт в системных процессах вне `.app` (например, сетевой процесс Safari), заморозкой не остановить. Для настоящей пофлоусовой фильтрации нужен Network Extension (платный Apple Developer ID).
